The GitHub Flow Collaboration Lifecycle

The standard branch-based workflow recommended by GitHub for continuous delivery.

Step 1

Create Branch

Branch off main with a descriptive name (e.g., feature/login)

git switch -c feat/xyz
Step 2

Make Commits

Add and commit logical, self-contained snapshots of code

git commit -m "..."
Step 3

Open Pull Request

Initiate discussion, run automated Actions CI tests, request reviews

gh pr create
Step 4

Review & Discuss

Peers leave comments, approve, or suggest inline changes

CODEOWNERS
Step 5

Merge & Deploy

Merge into main; branch auto-deleted and changes deployed

GitHub Security Triple Shield

How GitHub protects code, dependencies, and credentials across the supply chain.

Dependencies

Dependabot

  • Alerts: Scans dependency graph for CVE vulnerabilities
  • Security Updates: Automatically opens PRs to patch known CVEs
  • Version Updates: Keeps libraries up-to-date via dependabot.yml
Credentials

Secret Scanning

  • Alerts: Identifies leaked API tokens & keys across repos
  • Push Protection: Actively blocks commits containing secrets on git push
  • Partner Program: Immediately revokes compromised partner tokens
Code Analysis

CodeQL Code Scanning

  • SAST Engine: Treats code as a database to find semantic bugs
  • Data Flow Analysis: Traces tainted user inputs to vulnerable sinks
  • Automated Gating: Blocks pull requests if new security flaws are introduced
